# 23: Menus don’t close when selecting a recent file

**Category:** bug  
**Status:** resolved

## Problem

Choosing a **Recent files** entry opens the Guide (or runs the dirty prompt) but the **menu/popover stays open** until the user clicks away.

## Repro

1. Launch `nextguide` with a non-empty recent list.
2. File → Recent → pick a path.
3. Guide opens / prompts as designed, but the popover(s) remain visible.

> *This was generated by AI during triage.*

## Agent Brief

**Category:** bug  
**Summary:** Dismiss the Recent (and parent File) popover when the user selects a recent Guide path.

**Current behavior:**
Recent files live in a nested `MenuButton`/`Popover` inside the File popover. Each recent row is a `Button` that only sends an open message with the path. Neither the nested Recent popover nor the parent File popover is closed on click, so the UI stays open over the editor after the selection.

**Desired behavior:**
- Activating a recent-file item **immediately dismisses** the Recent popover and the File popover (or equivalent menu chrome).
- Then the existing open / dirty-prompt / load flow runs unchanged.
- Prefer the same dismiss behaviour for other File menu actions if they currently leave the File popover open (same class of bug); Recent is the required fix.

**Key interfaces:**
- Relm4/`gtk` File menu chrome: `MenuButton` + `Popover` for File and nested Recent.
- Recent item activation handler: today emits an “opened path” style message; it must also pop down / hide the relevant popovers (keep references or find parent popovers as needed).
- Session open / dirty-prompt path: no behavioural change beyond menu dismiss.

**Acceptance criteria:**
- [x] Selecting a recent file closes the Recent popover without clicking outside
- [x] The parent File popover is also closed (no leftover File menu over the window)
- [x] Open / dirty-prompt / load behaviour for recent files is otherwise unchanged
- [x] Manual check documented on the ticket when done (GTK UI; automated check optional)

**Out of scope:**
- Redesigning menus to `Gio::Menu` / a full menubar rewrite (unless a minimal change requires it)
- Changing recent-list size, storage, or ordering
- Issues #22 / #24 / #25 (fonts, launch focus, font picker)

## Answer

Named `file_popover` / `recent_popover` in the Relm4 File header chrome; `dismiss_file_menus()` pops both down. Recent-row `connect_clicked` dismisses immediately before `Msg::Opened`. File actions New / Open… / Save / Save As… / Quit also dismiss so the parent File popover does not linger. Open / dirty-prompt / load paths are otherwise unchanged.

### Manual check

1. Open a Guide so it appears under File → Recent; quit or New so Recent is non-empty.
2. File → Recent → choose the path: both Recent and File popovers must close immediately; Guide loads (or dirty prompt appears) as before.
3. Spot-check File → Open… / Save: File popover closes when the action runs.
