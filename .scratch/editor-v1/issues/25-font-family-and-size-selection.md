# 25: Font family and size selection

**Category:** enhancement  
**Status:** ready-for-agent  
**Blocked by:** 22 — Font table leak (Arial / `;` as body text)

## Problem

Editor v1 cannot choose **font family** or **font size** for Node bodies. Subset today is B/I/U + paragraphs + simple lists only.

Font-table **text leak** is **[22](22-font-support.md)** — fix that first.

> *This was generated by AI during triage.*

## Agent Brief

**Category:** enhancement  
**Summary:** Let users pick font family and size for body text, Round-tripping through `nextguide-rtf` for edited bodies.

**Current behavior:**
Body formatting exposes bold/italic/underline and lists. `SpanStyle` (or equivalent) has no face/size. The Guide bodies often use Arial / `\fs18`; users cannot set face or size in NextGuide. (Leak of the string `Arial` into text is ticket 22, not this ticket.)

**Desired behavior:**
- Format UI (menu and/or controls) to set **font family** and **font size** for the current body selection / typing.
- Agreed v1 set from triage:
  - **Families:** Arial and system default Sans (clear labels in UI).
  - **Sizes (points):** 9, 10, 11, 12, 14, 18, 24; **default 9** (aligns with common The Guide `\fs18` half-points).
- Edited bodies Round-trip face+size through `nextguide-rtf` writer/reader.
- Untouched bodies still preserve original opaque RTF bytes when not edited.
- Implement **after** ticket 22 so loads are not polluted by fonttbl text.

**Key interfaces:**
- `nextguide-rtf` edit model / `SpanStyle` (or successor fields): family + size for the agreed set; RTF `\fonttbl` / `\fN` / `\fsN` mapping for that set.
- Editor GTK `TextBuffer` / `TextTag` (or Pango attributes) and Format menu/controls.
- Save path: edited bodies emit subset RTF including face/size; untouched-byte policy unchanged.

**Acceptance criteria:**
- [ ] Ticket 22 is done (or this work assumes a clean load without `Arial;` text leaks)
- [ ] UI can set family to Arial or Sans and size to one of 9/10/11/12/14/18/24 (default 9 for new typing as agreed)
- [ ] Edited bodies Round-trip the chosen face+size through `nextguide-rtf` (library tests for at least one family and one size)
- [ ] Untouched bodies remain byte-preserving when not edited
- [ ] Existing B/I/U/list behaviour still works

**Out of scope:**
- Full system font picker / arbitrary faces
- Colour, highlight, or other exotic RTF attributes
- Perfect pixel match to Windows Arial metrics
- Changing ticket 22’s bugfix beyond depending on it
